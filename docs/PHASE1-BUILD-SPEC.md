# OctoGlyphs Phase 1 Build Spec

This document converts the broad GDD into the first buildable vertical slice. Phase 1 is deliberately local-first: make the Ink Tank loop feel complete, then prove the Open Ocean combat loop without multiplayer or server work.

## Phase 1 Goal

Build a polished single-player prototype that proves the complete player journey:

1. Start with a simple octo in the Ink Tank.
2. Collect gems generated by work activity or prototype timers.
3. Spend gems in the shop.
4. Unlock, equip, and visually stack traits.
5. Apply real stat modifiers from equipped traits.
6. Deploy into a local Open Ocean combat prototype.
7. Die, bank rewards, and return to the shop stronger.

If this loop is fun locally, server multiplayer becomes a scaling problem instead of a design gamble.

## Non-Goals For Phase 1

Do not build real multiplayer yet.

Do not build account login yet.

Do not parse prompt content. Only token/tool metadata should ever feed the game.

Do not hand-maintain every asset in one giant catalog file.

Do not introduce new art requirements except optional backgrounds or audio later.

## Core Scenes

### Ink Tank Scene

The Ink Tank is the safe home screen and idle growth space.

Required behavior:

- Octo idles gracefully when player is not controlling it.
- Player can manually control octo with mouse, keyboard, or gamepad.
- Gems spawn in the tank from prototype timers now, then OpenClaw metadata later.
- Gems have a small magnet radius and pull into the octo when close.
- Rare trait pickups can spawn, but autopilot should not collect them.
- Manual pickup of a trait unlocks or equips it for the current run.
- Closest gem indicator should point toward offscreen or distant gems.
- Camera should show enough map to make exploration feel real.
- Backgrounds should tile or cover cleanly using current Backgrounds folder.

### Shop And Loadout Scene

The shop is the permanent progression layer.

Required behavior:

- Display full generated catalog grouped by Bodies, Eyes, Hats, Clothes, and Boosts.
- Show owned, affordable, locked, and equipped states.
- Purchase with Data Gems.
- Purchased items are permanent account unlocks.
- Player selects one body, one eyes item, one hat, one clothes item, and one boost.
- Starter loadout is Blue body plus Regular eyes.
- Locked legendary and Halloween skins appear as aspirational items but are not core Phase 1 unlocks.

### Local Open Ocean Scene

This is not multiplayer yet. It exists to prove the survival loop.

Required behavior:

- Player deploys from Ink Tank or Shop into a larger hostile map.
- Enemies spawn, move, shoot or chase, and drop gems on death.
- Player auto-fires based on current stats and equipped weapon/boost behavior.
- Mass acts as health.
- Taking damage reduces mass.
- At zero mass, run ends.
- Death converts part of run mass into permanent Data Gems.
- Death screen summarizes mass peak, gems banked, kills, and run duration.
- Player can hatch again and return to Shop or Ink Tank.

## Asset Catalog Pipeline

Current shop uses a small curated catalog. Phase 1 should replace it with generated data from the sorted asset folders.

Source folder:

```text
PrimordialAI/sorted-octo-assets
```

Generated output should live in game source, for example:

```text
PrimordialAI/game/src/game/data/generatedAssetCatalog.js
```

The generator should scan:

- Bodies
- Eyes
- Hats
- Clothes
- Boosts or throwables
- Legendary octos
- Halloween octos if present

Each generated entry should include:

- Stable id derived from folder and filename.
- Display name derived from filename.
- Slot.
- Source path.
- Frame or static image type.
- Default rarity.
- Default cost.
- Default stat modifiers.
- Flags for modular versus locked full-body skin.

Do not encode all design metadata in generated output. Use a separate override table for hand-authored decisions.

Suggested files:

```text
assetCatalog.generated.js
assetCatalogOverrides.js
assetCatalog.js
```

`assetCatalog.generated.js` is machine-written.

`assetCatalogOverrides.js` is human-authored and safe to edit.

`assetCatalog.js` merges generated entries with overrides and exports the final runtime catalog.

## Rarity And Unlock Rules

### Starter

- Free.
- Available immediately.
- Used for Blue body and Regular eyes.

### Common

- Cheap.
- Appears early in shop.
- May appear as manual pickups in Ink Tank.
- Small stat modifiers.

### Uncommon

- Moderate cost.
- Requires some play before purchase.
- Better or more specialized modifiers.

### Rare

- Expensive.
- Lower pickup chance.
- More distinctive visuals and stronger effects.

### Epic

- Very expensive.
- Mostly shop or milestone unlocks.
- Strong build-defining modifiers.

### Legendary And Mythic

- Full-body authored skins or major prestige unlocks.
- Not modular unless explicitly marked.
- No accessories layered on top by default.
- Phase 1 can show them locked without fully implementing all passives.

## Slot Mechanical Identity

### Bodies

Bodies are character classes. They define the strongest base stat profile and any major passive.

Examples:

- Red: more damage, slightly less speed.
- Yellow or Gold: stronger magnet/economy identity.
- Metal or Gray: armor and retention identity.
- Midnight or Orange: speed/fire-rate identity.

### Eyes

Eyes represent perception, aim, luck, or emotional flavor. They should be small modifiers.

Typical stats:

- Luck.
- Magnet.
- Damage.
- Fire rate.
- Retention.

### Hats

Hats should feel like build-shaping modifiers. They can affect weapons, prompts, fire rate, or special behavior.

Typical stats:

- Fire rate.
- Damage.
- Luck.
- Special projectile behavior.

### Clothes

Clothes should mostly affect survivability and economy.

Typical stats:

- Armor.
- Retention.
- Speed.
- Gem value.

### Boosts

Boosts are the most game-mechanical accessory slot. They can behave like active or passive power items.

Typical stats:

- Damage.
- Fire rate.
- Special weapon type.
- Magnet.
- Burst effects.

## Stat System

Use the seven core stats from the GDD.

Base stats:

```text
speed = 1.0
fireRate = 1.0
damage = 1.0
armor = 0
magnet = 1.0
luck = 1.0
retention = 1.0
```

Final stats should be calculated from:

```text
body + eyes + hat + clothes + boost + run_mutations
```

Rules:

- Most modifiers stack additively.
- Multipliers should be clamped to avoid broken builds.
- Armor can be flat.
- Magnet modifies pickup radius.
- Luck modifies rare pickup chance and possibly crit/drop chance.
- Retention reduces mass lost on hit or death conversion loss.

Suggested Phase 1 clamps:

```text
speed: 0.65 to 2.25
fireRate: 0.5 to 3.0
damage: 0.5 to 3.0
armor: 0 to 10
magnet: 0.75 to 3.0
luck: 0.75 to 3.0
retention: 0.5 to 2.0
```

## Economy

### Data Gems

Permanent currency.

Earned by:

- Collecting gems in Ink Tank.
- Death conversion from Open Ocean run mass.
- Prototype debug grants during development.

Spent on:

- Bodies.
- Eyes.
- Hats.
- Clothes.
- Boosts.

### Run Mass

Temporary survival resource.

Gained by:

- Collecting gems during current run.
- Killing enemies in Open Ocean.

Lost by:

- Taking projectile damage.
- Death.

Converted to Data Gems on death using a simple Phase 1 formula first:

```text
bankedDataGems = floor(runMass * 0.25)
```

Later we can replace this with the more detailed GDD zero-sum formula.

## Manual Pickups And Swap Rules

Manual rare trait pickups are run rewards, not permanent purchases unless explicitly marked.

Rules:

- Autopilot ignores rare trait pickups.
- Manual control can collect them.
- If slot is empty, equip immediately for the run.
- If slot is occupied, show a swap prompt.
- Swap prompt must show current item stats versus found item stats.
- If player rejects swap, found item disappears or remains briefly, depending on feel.
- Purchased items remain permanently unlocked even if swapped out during a run.
- Found-only items vanish on death.

## Save Data

Local storage is enough for Phase 1.

Save:

- Data Gem wallet.
- Owned item ids.
- Equipped loadout ids.
- Current Ink Tank mass.
- Lifetime stats.
- Settings.

Run-only state should be clearly separated:

- Current run mass.
- Found temporary traits.
- Open Ocean kills.
- Run duration.

## Implementation Order

### Step 1: Stabilize Current Ink Tank Prototype

- Verify hat/clothes alignment across several bodies and hats.
- Verify pickup highlight removal.
- Verify background folder sync and tiling.
- If octo animation still feels jerky, switch to Phaser native animations.

### Step 2: Build Catalog Generator

- Scan sorted asset folders.
- Generate catalog entries.
- Merge overrides.
- Replace current 24-item catalog with full generated catalog.
- Keep starter items deterministic.

### Step 3: Build Real Stat Calculation

- Add stat calculator.
- Show final stats in UI.
- Apply speed and magnet first.
- Apply damage and fire rate in Open Ocean prototype.
- Add armor and retention once combat exists.

### Step 4: Upgrade Shop And Loadout UI

- Group by slot.
- Add purchase and equip buttons.
- Add rarity labels.
- Add stat comparison.
- Preserve save data.

### Step 5: Add Local Open Ocean Prototype

- New scene.
- Player deploy button.
- Enemy spawning.
- Projectile combat.
- Gem drops.
- Death and reward banking.

### Step 6: Add Polish Hooks

- Closest gem arrow.
- Frenzy mode placeholder.
- Tool metadata gem colors.
- Better pickup effects.
- Audio placeholders if assets exist.

## Phase 1 Acceptance Criteria

Phase 1 is complete when:

- The full asset library is visible in the shop or locked catalog.
- Player can buy and equip traits.
- Equipped traits visually appear on the octo.
- Equipped traits change actual stats.
- Ink Tank gem collection feels smooth.
- Rare manual pickups work and respect autopilot rules.
- Player can deploy into local Open Ocean.
- Player can kill enemies and collect dropped gems.
- Player can die and bank Data Gems.
- Death returns player to shop with permanent progress intact.

## Key Design Decision

The next engineering priority is not multiplayer. It is full catalog plus real stats.

The reason is simple: the asset library is the game’s strongest differentiator. Once every body, eye, hat, clothes item, and boost can enter the economy with real mechanics, the prototype stops feeling like a toy and starts feeling like a progression game.
